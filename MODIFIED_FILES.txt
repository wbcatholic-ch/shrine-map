V8-1-14-1007

길찾기 하단 끝여백 근본 구조 정리

원인
- 같은 #sheet-route의 하단 여백을 여러 곳이 동시에 관리하고 있었음
- #sheet-route 자체 padding-bottom
- #rs-bottom의 30px + Android gap
- route-result-showing의 28px + Android gap
- 이후 최종 규칙의 padding-bottom:0 / 10px
- 검색 전에는 #rs-bottom 자체가 display:none이어서,
  rs-bottom을 수정해도 실제 하단 끝여백에는 아무 영향이 없었음
- 그래서 상태에 따라 '붙었다 / 넓어졌다'가 반복됨

정리
1. 하단 끝여백 소유자를 #sheet-route 하나로 통일
- --oai-route-end-gap: 14px
- 휴대폰의 일반 길찾기 / 지도에서 추가 / 순례코스 보기 / 다음 순례지 길찾기
  모두 같은 끝여백 사용
- Android safe bottom gap도 같은 위치에서 한 번만 합산

2. #rs-bottom은 콘텐츠 좌우 패딩만 담당
- 하단 끝여백을 더 이상 담당하지 않음
- 결과 화면에서도 동일

3. 중복 제거
- route-result-showing의 28px bottom padding 제거
- #rs-bottom의 30px bottom padding 제거
- 결과 화면의 10px 임시 bottom padding 제거
- 검색 전 화면에서 아무 효과가 없던 rs-bottom 여백 패치 제거
- 사용하지 않던 oai-pilgrimage-route-context JS 클래스 제거

4. 가로 위치
- 입력창 가로 시작점은 기존 공통 #rs-top padding 규칙 그대로
- 성지 / 성당 / 피정 / 순례 관련 화면이 동일 기준 사용

5. 유지
- 일반 결과 화면 X 아래 이동
- 순례코스 보기 X 아래 이동
- 지도 중심 보정
- 거리/시간/카카오내비
- 지도에서 추가 편집
- 다음 순례지 길찾기 자동 재시도
